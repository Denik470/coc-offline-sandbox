# Автономный Android-контейнер 18.647.5

Это работающий стенд родной игровой логики. Полный визуальный клиент ещё не готов: оригинальный рендерер, камера, касания и редактор деревни не подключены.

Пакет `lab.coc.offline`, отдельное приложение **CoC Offline Lab**, без разрешения INTERNET. Рабочая сборка: `offline-combat-lab.apk`. Запуск не требует root, оригинальной установленной игры, ADB, Frida, сервера или снимка её памяти. APK содержит локальные данные деревни пользователя, не предназначен для публичного распространения.

Проверено на OnePlus CPH2767, Android 16 / API 36, ARM64:

- холодная загрузка 111 обычных CSV + animations.csv и upgrade_tasks.csv;
- чтение шести .scindex девятью родными сериализаторами;
- 119/119 проходов чтения таблиц и 119/119 проходов ссылок, финализация менеджера;
- свежие ClientAvatar, ClientHome, GameMode, LogicGame;
- полный loadHomeState, режим 1, основная деревня 419 построек / 48 ловушек / 37 препятствий, вторая 236 построек;
- родное клонирование аватара через ByteStream;
- NPC-аватар из записи NPC1, loadNpcAttackState возвращается в режиме 2;
- родная команда PlaceAttacker для варвара: код 0;
- 2048 боевых шагов: перемещение варвара, здоровье 4500 → 0, удаление из активных юнитов.

Кнопка «Проверить локальный NPC-бой» запускает проверку. Приборная панель пока текстовая. NPC-цель использует локальную деревню, а не оригинальную карту кампании NPC1. Аккаунт и армия создаются локально; сохранение/загрузка правок и полный исход боя пока не реализованы. Счётчик общего числа юнитов включает защитников и подкрепления: 6 → 10 не является количеством варваров.

## Сборка

`python3 outputs/clash-analysis-18.647.5/android-offline/build.py`

Скрипт использует подготовленные в `work/android-sdk` SDK 36, Build Tools 36.0.0, NDK 29.0.14206865 и локальный OpenJDK. Подпись только отладочная. Приватный ключ находится в `work/android-offline-build/lab.keystore`, не входит в исходники. Сборка включает копию восстановленного libg.so с проверкой SHA256, остальные библиотеки — из локального извлечения игры. Это не восстановленные исходники Supercell и не сборка libg.so из C++.

Изменения копии библиотеки для автономного контейнера:

1. DT_INIT перенаправлен с загрузочного преобразователя уже восстановленного образа на существующий RET `0xe49608`.
2. В 341 статическом инициализаторе восстановлены входные STP по сохранившимся сохранениям регистров и соответствующим эпилогам; карта в `../local-lab/static-initializer-patches.json`, генератор в `../tools/recover_initializer_frames.py`.
3. Вызов `0xf95a10` заменён NOP: это последняя запись метки `type=SinglePlayer/Practice/...` в JNI-телеметрию, отсутствующую в контейнере. Игровые проверки команды высадки и шаги симуляции не заменялись.
4. Локальные провайдеры задают стандартный регион, отключённые экспериментальные флаги, пустые календарь и события. Их ABI покрывает текущую логическую проверку; это ещё не полная платформенная обвязка.

## Следующий технический этап

Рендерер требует отдельного восстановления Java/JNI-моста GameApp, Surface, менеджеров графических ресурсов и связи визуальной сцены с этим локальным GameMode. Пока APK не рисует оригинальную деревню и не является полноценным автономным клиентом. Проверка входа в NPC-режим и короткого боя не доказывает, что завершение боя, все войска и все режимы работают.

Журналы собственного приложения: files/native-progress.txt и files/native-probe.txt. Исходники лабораторные: повторы проверки удерживают выделенные сессии; производственное управление жизненным циклом ещё требуется.

## Оригинальная графика: текущий эксперимент

`RenderActivity` работает в основном процессе, логический стенд — в `:logic`. Обе штатные библиотеки `libsupercell_clashofclans.so` и `libg.so` теперь успешно загружаются через `System.loadLibrary`. Ранний JNI_ERR устранён: добавлены видимость пакета `com.supercell.clashofclans` и Java-мосты `smxuhbhxh.ac` / `smxuhbhxh.aj`. Однократный диагностический JNI_OnLoad вернул 65538 (JNI 1.2); журнал `support-registration-check.txt`.

Восстановлены Android-диалоги и базовый WebView-мост. Теперь оригинальный загрузочный экран действительно рисуется в нашей Activity, без использования AssetManager установленной игры. Кадр asset-registry-screen.png, проверенная сборка offline-renderer-loading-lab.apk. Полная деревня ещё не появляется; остаётся предупреждение о некорректной установке, его причина не подтверждена. Загрузчик ещё использует метаданные установленной оригинальной игры. Автоматический повтор JNI_OnLoad после ошибки удалён. Краткие графические проверки завершаются остановкой только тестового пакета; установленная оригинальная игра не изменялась.

Режим `--ez inspectSupport true` читает ограниченный участок кода/таблицы входа без JNI-инициализации. Дополнительный `--ez initializeSupport true` разрешает единственный диагностический вызов в свежем процессе; повтор запрещён. Адрес `0x68ff58` является структурой диспетчера; её первый указатель ведёт на `0x5ec0a8`, а следующий внутренний callback — на `0x4454b4`. Первые 128 байтов функции совпали с восстановленным образом. Приближённая декомпиляция находится в `../local-lab/support-decompiled`.

Этот графический эксперимент пока использует метаданные установленного оригинального пакета и не является автономным результатом. Проверенная боевая сборка `offline-combat-lab.apk` от установленной игры не зависит. Цель — сохранить оригинальные графику и интерфейс и подключить их к автономной логике; текстовая панель остаётся только диагностикой. `offline-lab.apk` — экспериментальная сборка.

## Проверка после раздельной упаковки ресурсов

Canonical CSV из assets-current остаются в исходном виде для оригинальной оболочки. Распакованные копии для headless-логики находятся отдельно в assets/decoded/. После изменения повторно проверены полное состояние деревни, высадка и 2048 шагов боя: decoded-assets-combat-check.txt. В графическом процессе наблюдаются 116 таблиц; отсутствующие индексы 4/54/90 также отсутствовали в исходном runtime-реестре, поэтому само их отсутствие не считается доказанной причиной предупреждения.
